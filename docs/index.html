01 — Abstract

Which content pages with real search demand but no observed AI-referral traffic most resemble the pages that do get AI-referred sessions — and how confidently can that resemblance be ranked?

Because AI-referral sessions are sparse (observed in only ~6.4% of demand-worthy pages), this work frames the problem as opportunity ranking rather than binary classification, evaluated with precision@K and lift@K instead of accuracy or AUC. A five-feature logistic regression model, trained and validated with a client-grouped split to prevent cross-client leakage, is compared against a transparent single-signal baseline rule. The model achieves a lift@K of 5.02x over random selection (18.44% precision@K against a 3.67% base rate), a number confirmed honest through two dedicated leakage audits — one isolating split-level client leakage, one isolating feature-level label leakage. The result is a ranked, reason-coded queue of decision-support recommendations, framed throughout as observed and directional rather than causal or algorithmic-certainty claims.

02 — Introduction

The question behind the ranking

Content teams routinely face a practical, unglamorous question: of all the pages that get real search demand, which ones deserve attention first? Historically this decision leaned on total traffic or recency. The rise of AI-mediated search — users discovering pages through AI assistants and answer engines rather than only traditional result clicks — adds a new axis worth watching: some pages already earn AI-referred sessions, and many demand-worthy pages that plausibly could earn them currently do not.

This raises a decision-support question rather than a scientific one: among demand-worthy pages with no observed AI-referral traffic, which most resemble the pages that already receive it? A content team cannot manually audit every page with search demand — some ranked starting point is needed. The purpose of this work is to build that ranked starting point honestly: transparent enough to trust, validated rigorously enough that its numbers survive scrutiny, and framed carefully enough not to overclaim what it can and cannot know about why AI referral happens.

Two constraints shape everything that follows. First, the outcome of interest is rare in the data, which rules out standard classification and points toward ranking. Second, this analysis works entirely from anonymized, aggregate search behavior data — no client identity, no page content, no causal claim about any platform's underlying algorithm is possible or attempted here. What follows is a decision-support tool, not a prediction of algorithmic behavior.

03 — Data

One warehouse, one partition, five safe features

This work uses the FlyRank ML Internship warehouse release (Hugging Face, hf://datasets/FlyRank/internship-warehouse), queried via DuckDB. All analysis is scoped to a single monthly partition, month = 2026-03, to keep the feature set and label definition stable within one observation window.

The working population is restricted to demand-worthy pages — total_gsc_impressions_month ≥ 100 — since pages with negligible search demand aren't meaningful candidates for an opportunity judgment either way. Within this population, the label has_ai_sessions_month is sparse: only ~6.4% of demand-worthy rows show an observed AI-referred session. This sparsity is a first-class design constraint, not a footnote.

The five-feature frame

Every feature was chosen because it is knowable independent of the AI-referral outcome — ruling out an entire class of subtle leakage, not just the obvious case:

GSC = Search Console measurement, structurally independent of AI-referral tracking. Static = fixed at publish time.

Excluded by design

sessions_ai_month is the same-month precursor to the label itself. Including it produces label leakage, not signal — demonstrated directly in Results as an audit check, never used in the reported model.

Consistent with the repo's public-data rules, no client names, domains, URLs, titles, or raw keyword data appear anywhere in this analysis, the underlying notebooks, or this paper. All figures are reported at the aggregate/statistical level only.

04 — Methodology

Ranking, not classification

With AI-referral sessions present in only ~6.4% of demand-worthy rows, a binary classifier evaluated on accuracy or AUC would optimize for the wrong thing — most pages are negatives by construction. This work is framed instead as an opportunity-ranking problem, evaluated with precision@K and lift@K: if you only have time to review K pages, how much better is this ranking than reviewing K pages at random?

Baseline — one signal, defended

A transparent, hand-written scoring rule ranks pages using a single, auditable signal: action_score is the percentile rank of impression volume within the eligible pool. A second candidate — days_since_last_update, a staleness proxy — was tested independently and returned a Mixed result: a weak, non-monotonic relationship, not a confirming pattern. Rather than force an unproven signal into the rule, staleness was given zero weight and excluded entirely. The baseline reports one signal it can defend, not two of uneven trustworthiness blended together.

Model — interpretable first

Logistic regression is the primary model, chosen for interpretability and because it extends the baseline's transparent-scoring philosophy. A random forest was trained as a secondary check on the same features and split. Gradient boosting was deliberately excluded — given the feature set's simplicity and label sparsity, added complexity was judged unlikely to earn its keep.

Validation — grouped by client, non-negotiable

All splits use GroupShuffleSplit on client_hash_id, ensuring no client's pages appear in both train and test. Without this, a model can partially learn to recognize clients rather than page-level opportunity signal — inflating apparent performance in a way that would not generalize to a new client's site. The validation audit (Results) quantifies exactly how much this matters.

Evaluation scope

Lift@K validation uses the full demand-worthy slice, not a zero-AI-session-only pool — lift@K requires positives to exist in the evaluation set to be meaningful.

05 — Results

5.02x lift, checked two ways

Three approaches were evaluated on the identical client-grouped test split (K=244, base rate 3.67%):

Model Precision@K Lift@K
Baseline (impression-rank rule) 11.07% 3.01x
Logistic Regression Reported 18.44% 5.02x
Random Forest 13.93% 3.79x

Logistic regression beats the transparent baseline by a meaningful margin — confirming the additional four features carry real signal beyond impression volume alone — and also outperforms the more flexible random forest. Added complexity did not buy added performance here, supporting this paper's complexity-discipline stance rather than undermining it.

What the model leans on

Both models independently converge on the same top driver: days_with_impressions_month ranks first in logistic regression's standardized coefficients and first in random forest's permutation importance. This cross-model agreement matters — it isn't one model's idiosyncrasy.

Sanity check

The top feature is an independent, non-leaky Search Console signal — the same signal family the baseline already trusts. Had a near-duplicate of the label topped this list instead, that would have been a red flag demanding investigation. It didn't happen. As expected under the earlier Mixed verdict, days_since_update_month ranks low in both models (LR: 8th of 11; RF: 5th of 9) — independent confirmation the baseline was right to exclude it.

Two leakage audits, both clean

Split-level check. A naive random split measured lift@K at 5.58x — inflated by client-identity memorization, since rows from the same client could appear in both train and test. Moving to a grouped split drops lift to 5.02x. The modest size of this gap says most of the model's performance survives once client leakage is removed.

Feature-level check. Including sessions_ai_month — the label's direct source column — inflates lift@K to 19.97x and precision@K to 73.36%. This roughly fourfold jump, far larger than the split-leakage effect, confirms the feature is circular: it doesn't predict the outcome, it restates it.

Where the model and baseline disagree

Of the 127 pages logistic regression ranks in its top-244 that the baseline does not, 21.3% are true positives. Of the 127 pages the baseline ranks that logistic regression does not, only 7.1% are true positives. This roughly 3x gap is the page-level expression of the aggregate lift@K difference — the model finds a meaningfully different, more accurate set of pages, not just a better-scored version of the same set.

Together, these results support the paper's headline claim: a five-feature, leakage-audited logistic regression model, evaluated on unseen clients, ranks AI-referral opportunity pages at roughly 5x random and roughly 1.7x the transparent baseline.

06 — Limitations & Honest Framing

What this is, and isn't

This work is decision-support, not prediction of causal mechanism. Nothing here claims to know why an AI platform referred a session to one page and not another, nor does it predict changes in any platform's underlying ranking algorithm. All results describe observed associations in one month of anonymized search behavior data — directional signals for where to look next, not guarantees of outcome.

Single-month scope

All modeling uses the March 2026 partition only. AI-referral behavior is an early-stage, fast-moving pattern — one month is one snapshot, not a stable trend. Results are a starting hypothesis for the current period, to be re-validated as new partitions arrive.

Sparse-label statistics

With the label present in only ~6.4% of rows, even leakage-audited metrics carry wider uncertainty than a denser-label problem would. Lift@K of 5.02x is a meaningful, validated improvement over random selection — not a claim of high confidence on any individual page.

The throughline

Every number in this paper survived scrutiny before being reported: a client-grouped split ruling out identity memorization, an explicit exclusion test ruling out label circularity, and a documented Mixed verdict that kept a weak signal out of the baseline rather than force it in. The principle, applied consistently: report only what survives scrutiny, and show the scrutiny itself.

No client-identifying information

Consistent with the repo's data-use rules, this analysis contains no client names, domains, URLs, page titles, or raw keyword data — only aggregate statistical results.

07 — Ranked Recommendations

Three cases, read with judgment

The model's output is a ranked opportunity queue — demand-worthy pages with no currently observed AI-referral traffic, ordered by predicted resemblance to pages that already earn it, each traceable back to specific, human-checkable signals.

Case 1 — the model catches what the baseline misses
feedly article · 342 impressions · avg position 8.3

Ranks highly under logistic regression despite modest raw volume, because content type and position carry weight beyond impressions alone. The impression-only baseline would not have surfaced this page — the clearest evidence of the model's added value.

Case 2 — the baseline catches what the model misses
keyword article · 8,610 impressions · avg position 5.4

An intuitively strong candidate by raw volume, ranked lower by the model when other signals pull against it. Worth manual review rather than dismissal — a case where a reviewer should sanity-check the model, not assume it's simply right.

Case 3 — a false positive worth a second look
keyword article · 2,114 impressions · avg position 30.1

High volume but weak position, yet ranks in the model's top tier — an example of where volume/type can outweigh position, and where human review adds value the model alone doesn't provide.

Suggested action framing

Strong on both leading signals

Highest-confidence review candidates — days-with-impressions and position both point the same direction.

High-volume outliers pulled down by other signals

Manual review — the model may be right to deprioritize, or missing context aggregate features can't capture.

High-volume, weak-position, ranked highly anyway

Lower-confidence hits — treat as requiring human confirmation before action.

This queue is a starting point for human review, not an autonomous action list.
